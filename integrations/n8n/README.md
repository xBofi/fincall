# n8n workflows for Fincall

Fincall talks to n8n in two directions:

- **Call events → n8n** (fire and forget). After every turn the backend compares the call state
  before and after and posts what happened to every URL in `BC_N8N_WEBHOOK_URL`
  (comma-separated): `call.started`, `emergency.detected`, `ticket.created`,
  `handoff.requested` and `call.ended`. The code is in
  `backend/src/building_call/integrations/` (`events.py`, `webhooks.py`).
- **Agent → n8n → agent** (a tool, during the call). After the ticket is saved, the graph's
  `book_visit` node calls `BC_N8N_TOOL_URL` and waits up to `BC_N8N_TOOL_TIMEOUT_S` (1.5 s) for
  a slot in the maintainer's calendar. If n8n answers in time with a valid slot, the assistant
  says it; otherwise the call closes exactly as it would without n8n
  (`integrations/n8n_tool.py`, node `book_visit` in `graph/nodes.py`).

| File | Webhook path | What it does |
|---|---|---|
| `ticket-to-maintainer.json` | `/webhook/fincall-ticket` | `ticket.created` → e-mail and Slack message to the maintainer |
| `urgent-escalation.json` | `/webhook/fincall-urgent` | emergencies, high-urgency tickets and handoffs → SMS to the on-call coordinator (Twilio) |
| `book-visit-google-calendar.json` | `/webhook/fincall-book-visit` | the `book_visit` tool: next working day 9–11, checks Google Calendar, holds the slot, answers `{booked, slot_text, booking_id}` |

**Languages.** Every event and tool request carries the call's `language`: one of the six
codes of `backend/src/building_call/i18n/locales/` (`es`, `en`, `ca`, `ar`, `hi`, `ur`). The
booking workflow writes `slot_text` in that language and script (it is spoken as is), and the
e-mail, Slack and SMS texts follow it too. Each Code node has a small `LANGS`/`L` table with all
six: adding a language is one entry there, and an unknown code falls back to English. Fincall's
slot check accepts any script (Latin, Arabic, Devanagari) but refuses markup, quotes, braces and
control characters.

The JSON files are generated by `build_workflows.py` so the shared Code nodes stay readable;
edit the script and run `python integrations/n8n/build_workflows.py` instead of editing JSON.

## Security: signed, timestamped, idempotent

Every request from Fincall (events and the tool) carries:

| Header | Value |
|---|---|
| `X-Fincall-Event` | event type, e.g. `ticket.created` (`tool.book_visit` for the tool) |
| `X-Fincall-Timestamp` | Unix seconds when it was signed |
| `X-Fincall-Signature` | `v1=` + hex HMAC-SHA256(secret, `"<timestamp>.<body>"`) |
| `Idempotency-Key` | the event id, the same on every retry |

The first Code node of each workflow (**Verify signature**) rebuilds the canonical body, checks
the HMAC in constant time and refuses anything older than 5 minutes. The **Skip retried events**
node (Remove Duplicates, "items repeated in previous executions") drops a retry that n8n
already processed, using `Idempotency-Key`.

Fincall retries a delivery up to `BC_N8N_WEBHOOK_ATTEMPTS` (4) times with exponential backoff and
jitter when n8n is unreachable or answers 408/425/429/5xx, honours a short `Retry-After`, and never
retries other 4xx. A call never waits for an event delivery.

The caller's phone number is never sent. Events carry the building, the apartment, category,
urgency, the summary and the maintainer.

## Run it locally

1. Give n8n and the backend the same secret. Keep it in SecretBroker (id
   `bc-n8n-webhook-secret`) and run both through `sb run`, so the value is never written in a
   file:

   ```powershell
   # repo root: starts n8n with FINCALL_WEBHOOK_SECRET=<the secret>
   sb run -- docker compose --profile n8n up -d n8n
   ```

   The compose service sets `NODE_FUNCTION_ALLOW_BUILTIN=crypto` (the Code node needs `crypto`),
   `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` (to read `FINCALL_WEBHOOK_SECRET`) and
   `FINCALL_CALENDAR_DEMO=true` (the booking workflow answers a demo slot without Google).

2. Open <http://localhost:5678>, create the owner account, then import the three files:
   **Workflows → ⋯ → Import from File**. Or from the CLI:

   ```powershell
   docker exec building-call-n8n n8n import:workflow --separate --input=/workflows
   ```

3. In each workflow set the credentials of its action nodes (SMTP, Slack, Twilio, Google
   Calendar) and change the example addresses and numbers, then **Activate** it. Without
   credentials the verification and routing nodes still run; only the action node fails, which is
   enough to see the events arrive.

4. Point the backend at n8n (`backend/.env`, secret through SecretBroker):

   ```dotenv
   BC_N8N_WEBHOOK_URL=http://localhost:5678/webhook/fincall-ticket,http://localhost:5678/webhook/fincall-urgent
   BC_N8N_TOOL_URL=http://localhost:5678/webhook/fincall-book-visit
   ```

   and start the API with `sb run -- uv run building-call`. `GET /api/health` shows
   `"n8n": {"events": true, "tool": true}`.

5. Make a call from the console (Simular llamada). The **Executions** tab of each workflow shows
   the signed event; with the demo calendar the assistant closes with "Según su agenda puede
   pasar el jueves 26 entre las 9:00 y las 11:00…".

`docs/integrations/` has screenshots of a local run.

## Event payloads

```json
{
  "id": "evt_3f0c…",
  "type": "ticket.created",
  "created_at": "2026-11-24T10:15:02+00:00",
  "call_id": "llam-1a2b3c4d5e6f",
  "language": "es",
  "data": {
    "incident_id": "inc-…",
    "category": "plumbing",
    "urgency": "high",
    "work_type": "repair",
    "estate_id": "finca-mayor-12",
    "building": "Calle Mayor 12",
    "home_id": "finca-mayor-12-u-3B",
    "apartment": "3º B",
    "summary": "Fuga de agua en el baño que inunda el suelo",
    "specialist_id": "esp-fontanero",
    "specialist_name": "Fontanería Pérez",
    "needs_administrator": false,
    "review_reason": null
  }
}
```

`call.ended` adds `result`, `duration_s`, `turns`, `needs_review` and `visit` (the tool's
outcome). `handoff.requested` has `reason` (`caller_asked_for_a_person` or why the assistant
gave up). `emergency.detected` has the building, apartment, category and what the caller said.

## The tool contract (`book_visit`)

Request (signed like the events, `X-Fincall-Event: tool.book_visit`):

```json
{"tool": "book_visit", "call_id": "llam-…", "language": "es", "incident_id": "inc-…", "category": "plumbing",
 "urgency": "high", "estate_id": "finca-mayor-12", "building": "Calle Mayor 12",
 "apartment": "3º B", "specialist_id": "esp-fontanero", "specialist_name": "Fontanería Pérez",
 "summary": "…"}
```

Answer (from a **Respond to Webhook** node):

```json
{"booked": true, "slot_text": "el jueves 26 entre las 9:00 y las 11:00", "booking_id": "…"}
```

`slot_text` is spoken to the caller, so Fincall only accepts a single line of up to 80
characters of plain text; anything else, `booked` not exactly `true`, a non-2xx answer or a
timeout falls back to the usual closing ("he will call you to arrange the visit").

The node only runs for a repair with a maintainer assigned and never in an emergency.

**Business rule (Andreu, 2026-11-24).** The assistant never gives a firm time: nobody has spoken
to the maintainer yet. When the n8n tool is enabled it may offer a slot, but always as
**provisional, pending confirmation by the maintainer**, and that is what the closing says in
every language (`notify_channel.visit_notice`; a test fails if a language's wording drops it).
The tool is **off by default**: it only exists when `BC_N8N_TOOL_URL` is set.
